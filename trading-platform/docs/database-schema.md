# Database schema

PostgreSQL 16. Schema changes are made only through Alembic migrations in
`backend/migrations/versions/`. A test compares the models with the migrated
database, so the two cannot drift apart.

**Built** tables exist in migration `0001`. **Planned** tables are the design
for later phases; each arrives with the code that uses it, in its own migration.

## Conventions

| Rule | Detail |
|---|---|
| Tenant key | Every table that holds a user's data has a non-null `user_id` referencing `users.id`. One user is one tenant. |
| Row-level security | Enabled and forced on every table. Policies compare `user_id` with the transaction's access context. A table of shared reference data must be listed explicitly in a test to be exempt. |
| Privileges | The application role gets only the statements and columns it needs. Identifiers, owners and creation times are not updatable by it at all. |
| Identifiers | UUIDs generated by the database, except append-only logs, which use a sequence so they sort by arrival. |
| Time | `timestamptz`, stored in UTC. |
| Money and quantity | `numeric`, never floating point (from Phase 2). |
| Enumerations | Text with a check constraint, so adding a value is a simple migration. |
| Secrets | Stored as a hash when they only need checking, or encrypted with the row bound in when they must be read back. Never plain. |
| Idempotency | A unique constraint, not application logic, is what prevents a duplicate. |
| Append-only | Audit and event tables allow insert and select only; a trigger refuses updates, deletes and truncation. |

## Access context

Each transaction sets two values that the policies read:

| Mode | Used by | Sees |
|---|---|---|
| `none` | Default | Nothing. Code that forgets to set a context gets no rows. |
| `tenant` | A signed-in user | Only rows where `user_id` is theirs |
| `staff` | The admin API | Profiles, session metadata, audit logs. Never credential tables. |
| `system` | Sign-in and token flows, workers | Everything. Allowed in a short list of files, enforced by a test. |

## Built: identity and audit (migration 0001)

### users
The account and tenant.

| Column | Type | Notes |
|---|---|---|
| id | uuid | Primary key |
| email | citext | Unique, case-insensitive. Not updatable by the application role. |
| display_name, timezone | text | Profile |
| role | text | `user`, `support_admin`, `super_admin` |
| status | text | `active`, `suspended` |
| suspended_reason | text | |
| email_verified_at | timestamptz | Set only by sign-up and reset flows |
| mfa_enabled | boolean | Display mirror; the enforced value is in `user_credentials` |
| last_login_at, created_at, updated_at | timestamptz | |

A trigger enforces: role and status change only in the staff context, never on
one's own account, role changes only by a super admin, and support admins only
on regular users.

### user_credentials
Sign-in secrets, split from the profile so the staff context cannot read them.

| Column | Type | Notes |
|---|---|---|
| user_id | uuid | Primary key, references users |
| password_hash | text | Argon2id |
| password_changed_at | timestamptz | |
| totp_secret_enc | text | AES-256-GCM, bound to this user |
| totp_enabled_at | timestamptz | Null until a code has been confirmed |
| totp_last_step | bigint | Last accepted time step; blocks replay |

### sessions
| Column | Type | Notes |
|---|---|---|
| id | uuid | Primary key |
| user_id | uuid | Not updatable |
| token_hash | text | SHA-256 of the cookie value; unique |
| created_at, last_seen_at, expires_at | timestamptz | Idle and absolute expiry |
| revoked_at, revoked_reason | | Once set, never cleared (trigger) |
| pending_mfa | boolean | True between password and second factor |
| mfa_at | timestamptz | When a second factor was presented |
| mfa_failed_attempts | smallint | Session ends at five |
| ip, user_agent | text | |

Only sign-in code creates sessions. Staff can revoke one and nothing else.

### email_tokens
Single-use links for email confirmation and password reset: `user_id`,
`purpose`, `token_hash` (unique), `expires_at`, `used_at`.

### recovery_codes
Backup codes for two-factor: `user_id`, `code_hash`, `used_at`. Unique on user
plus hash.

### audit_logs
| Column | Type | Notes |
|---|---|---|
| id | bigint identity | Primary key |
| created_at | timestamptz | |
| user_id | uuid | The account the event concerns |
| actor_user_id, actor_role | | Who did it; differs when staff act |
| action | text | For example `auth.login.failed`, `admin.user.suspended` |
| target_type, target_id | text | |
| ip, user_agent, request_id | text | |
| detail | jsonb | Never contains secrets; enforced in code and by a test |

Writers must name themselves as the actor. Nothing can update or delete a row.

## Planned

Key columns and constraints only. All have `user_id`, row-level security and
`created_at` unless marked shared.

### Phase 2: strategies, webhooks, signals

| Table | Purpose | Key points |
|---|---|---|
| strategies | What an alert should do | `public_id` unique per user, name, status, execution mode (`paper`, `semi_auto`, `auto`), default sizing, stop loss and take profit defaults, schedule, `version` |
| strategy_versions | History of every change | Full snapshot per version, who changed it |
| webhooks | Credentials for incoming alerts | `token_hash` unique, optional passphrase hash, strategy, enabled, revoked_at, last_received_at |
| signals | Every alert received | Unique `(webhook_id, signal_id)` for idempotency; raw payload, parsed fields, signal time, received time, status, rejection reason |
| outbox | Work to dispatch | Written in the same transaction as the signal; the sweeper reads it |
| dead_letters | Work that exhausted its retries | For operator review |

### Phase 3: orders and paper trading

| Table | Purpose | Key points |
|---|---|---|
| broker_accounts | A connected account | Broker (`kite`, `mt5`, `mt4`, `paper`), label, execution mode, paused, kill switch, connection status |
| strategy_accounts | Which accounts a strategy trades | Sizing mode and value, enabled |
| orders | One order per signal per account | Unique `(signal_id, broker_account_id, leg)`; unique `client_order_id`; state; side, type, quantity, prices; broker order id; filled quantity, average price; `is_paper`; lease owner and expiry; timestamps for latency |
| order_events | Every state change | Append-only |
| fills | Executions reported by a broker | Quantity, price, fee, broker trade id; unique per broker trade; `is_paper` |
| positions | Current position per account and instrument | Updated from fills; `is_paper` |
| paper_accounts | Simulated balance and cost settings | |

### Phase 4: brokers and instruments

| Table | Purpose | Key points |
|---|---|---|
| broker_credentials | Secrets for direct adapters | Encrypted, bound to the account; no policy grants staff access |
| bridge_devices | A paired Expert Advisor or agent | `token_hash`, last heartbeat, terminal build, account number |
| bridge_instructions | Work for a bridge to execute | Claimed with a lease; result reported back |
| instruments (shared) | Broker instrument master | Exchange, trading symbol, token, expiry, strike, option type, lot size, tick size |
| instrument_mappings | Alert symbol to broker instrument | Per user, optionally per account |

### Phase 5: risk

| Table | Purpose | Key points |
|---|---|---|
| risk_profiles | Limits at global, account or strategy scope | Maximum quantity, positions, daily loss, daily trades, exposure, slippage, signal age; allowed sessions and instruments; kill switch |
| risk_decisions | Every check that rejected an order | The rule and the values compared |
| reconciliation_runs | Results of comparing with the broker | Differences found |
